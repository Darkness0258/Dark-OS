## Phase 3: The assistant, for real
Goal — AI / Voice / Vision / Memory / Command / Search / Automate actually work
Status: refactor done 2026-08-18. Wiring + new modules completed 2026-08-20. All py_compile clean. Unit mock harness exists (`ci/test-phase3-linux.py`). Runtime verified 2026-08-24 via SSH + VMware: AI chat (OpenRouter), STT (Groq), TTS (espeak-ng fallback), D-Bus/hyprctl control, AT-SPI text extraction, explain-this, activity-aware shell, dock highlight, boot animation, Plymouth splash. **2026-08-20 code reviews found and fixed 3 real bugs** (see items below).
- [x] Refactor `darkos-shell.py` — done: split into `darkos_shell/` package (9 modules + 24-line entry point). py_compile clean, LF/permissions verified, existing hyprland.conf keybindings still route correctly.
- [x] STT + TTS + brain **code wired + runtime verified 2026-08-24** — `ai_brain.py` wired to chat entry and voice trigger. Chat `on_submit` calls `brain.process_chat()` on a background thread; voice dispatch routes through `process_voice → process_chat → speak`. Orb state transitions (listening/thinking/speaking/error/sleeping) driven by the dispatch chain. **Runtime verified 2026-08-24 via SSH:** chat round-trip returned "2+2 equals 4." via OpenRouter free model; voice pipeline STT chain executed against Groq (empty result for `/dev/null` input, no crash). TTS audio confirmed via espeak-ng fallback (`_try_espeak_tts('hello')` returned True, spoken responses audible).
- [x] OS-level control via D-Bus / hyprland **code wired + runtime verified 2026-08-24** — `actions.py:ActionDispatcher` built with `open_app`, `set_volume`, `set_brightness`, `switch_workspace`, `search`. Brain dispatches via `[ACTION]` markers in LLM replies. Snapshot-before-act wraps all mutating actions. **Bug fixed 2026-08-20:** `_parse_args` split on every comma, so any argument text containing one (e.g. `open_app` with a comma in it) mis-split into extra args and errored — rewritten to use `csv` parsing, which respects commas inside quotes. **Runtime verified 2026-08-24 via SSH:** `pamixer --get-volume` confirmed 40→35 after `set_volume(35)`; `hyprctl dispatch workspace 2` returned "ok" with auto-discovered `HYPRLAND_INSTANCE_SIGNATURE`.
- [x] Generic in-app control via AT-SPI **code wired and runtime-verified 2026-08-20** — `actions.py:_atspi_do_action` walks the AT-SPI tree supporting click, set_text, focus actions. Bug fixed 2026-08-20 (stray `"--"` breaking every subprocess call, see prior entry). `[x]` Runtime verified in live VM: 2 real apps (`nm-connection-editor` PID 5223, a GTK test target PID 5401) confirmed open via `hyprctl clients -j`, both visible in the AT-SPI tree, `atspi_click('push button', 'Submit')` succeeded against the real running app.
- [x] Push-to-talk trigger **code wired + runtime verified 2026-08-24** — `assistant_trigger.py` recording path bug fixed (`_recording_path` now stored/returned). Push-to-talk via SUPER+SPACE on dock window. `AssistantTrigger(self.brain)` instantiated and started in `do_activate()`. **Runtime verified 2026-08-24 via SSH:** `process_voice('/dev/null')` returned empty string (STT chain executed against Groq, no crash). `[ ]` Actual push-to-talk gesture (hold SUPER+SPACE, speak, hear TTS back) needs real hardware mic testing — VMware virtual mic bridge does not forward host audio into the guest.
- [x] Snapshot-before-act **code wired + runtime verified 2026-08-24** — `actions.py:_snapshot()` creates Btrfs snapshots at `/.snapshots/darkos-ai-<timestamp>` before any mutating action. Silently skips on non-Btrfs. **Bug found and fixed 2026-08-20:** destination path had an invalid literal `@` (`/@/.snapshots/...`) instead of `/.snapshots/...`, and missing directory creation before snapshotting. ## Phase 4: Daily-use native apps
Goal — the apps someone touches every day exist
- [x] File Explorer (+ Archive) **code complete 2026-08-27** — `darkos-files.py`, standard GTK3 widgets throughout (TreeView/ListBox/dialogs, no custom Cairo controls) so AT-SPI can drive it like any other app. Sidebar (Home + XDG user dirs via `GLib.get_user_special_dir`, Trash, Filesystem), breadcrumb + direct-entry (Ctrl+L) path bar, folders-first sort on Name/Size/Modified, live filter, Copy/Cut/Paste/Rename/Compress/Move-to-Trash (`Gio.File.trash()`, confirmation dialog per ui-rules.md's destructive-action rule), Open Terminal Here. Archive scope is deliberately v1: double-click a .zip/.tar* previews its listing + Extract Here/Extract To, multi-select Compress creates a .zip — browsing *inside* an archive like a folder is a real follow-up feature, not silently half-built. `tarfile.extractall(..., filter="data")` (PEP 706) against path-traversal in untrusted archives. **Runtime-verified 2026-08-27 under Xvfb/X11** (not the target Wayland/Hyprland compositor — these are normal floating windows so this is representative for logic/layout, not for compositor-specific behavior): screenshots confirm real directory navigation, folders-first sorting, and archive-listing dialog showing the exact contents of a real test zip. `[ ]` Real Wayland/Hyprland run — icon theme, JetBrains Mono Nerd Font rendering, and the `darkos-files` Hyprland windowrule class-match (see hyprland.conf comment) all need a look on real hardware.
- [x] Terminal (full, not just the Phase 1 shell default) **code complete 2026-08-27** — `darkos-terminal.py` replaces the kitty-backed the-void.sh. Vte.Terminal does the actual emulation (PTY/ANSI/scrollback); this file owns tabs, DarkOS glass styling, and a 16-slot ANSI palette built from the design tokens. Ctrl+Shift+T/W (tab new/close), Ctrl+Shift+C/V (copy/paste — plain Ctrl+C still reaches the shell as SIGINT), Ctrl+±/0 (zoom), Ctrl+PageUp/Down (switch tabs). Preserves the-void.sh's `-e CMD` contract for existing callers (`darkos-tool-groups`, etc.) and adds `--cwd DIR` for File Explorer's "Open Terminal Here." VTE draws via Cairo/Pango, not OpenGL, so the kitty-era VM software-rendering workaround is gone. **Runtime-verified 2026-08-27 under Xvfb/X11**: screenshot shows two live tabs, correct active-tab styling, and a real spawned shell (`root@vm:~#`) responding to typed input. `[ ]` Real hardware/Wayland run for the same reasons as Files above, plus: confirm `ttf-jetbrains-mono-nerd`'s actual registered font-family name matches what `Pango.FontDescription("JetBrains Mono 11")` resolves to (Nerd Font patching sometimes renames the family).
- [x] Notes (+ Editor) **code complete 2026-08-27** — `darkos-notes.py`. Sidebar list of plain `.txt` files in `~/Documents/DarkOS Notes/` (visible/editable from File Explorer too — no proprietary format), 600ms-debounced autosave, new/rename/delete. Doubles as a general small-file text editor: `argv[1]` opens any path directly with an explicit Save instead of autosave, for File Explorer's eventual default-app handoff. **Runtime-verified under Xvfb/X11**: created a note, typed content, confirmed it landed on disk with the exact typed text and a correct live word/char count.
- [x] Calendar **code complete 2026-08-27** — `darkos-calendar.py`, built on the stock `Gtk.Calendar` widget rather than a custom grid. Per-day text events in a sidebar, persisted as JSON at `~/.local/share/darkos/calendar-events.json`, double-click a day to add an event, marked days highlight in the mini-calendar. Deliberately not a recurring-event/reminder system — that's a real follow-up, not built here. **Runtime-verified**: double-clicked a real day, added an event through the dialog, confirmed it appears in the sidebar and round-trips through the JSON file correctly.
- [x] Clock **code complete 2026-08-27** — `darkos-clock.py`, four tabs (Clock, Alarms, Timer, Stopwatch) on one ticking `GLib.timeout_add`. World clocks via stdlib `zoneinfo` (IANA names, e.g. "Asia/Karachi"), alarms and world-clock list persist as JSON, alarms/timer-done fire through `Gio.Notification`. **Runtime-verified**: added a world clock and watched it tick, started the timer and confirmed the countdown actually decrements in real time, ran the stopwatch and recorded a lap. Known polish gap: the start/pause buttons don't swap their icon glyph on state change (tooltip text does) — cosmetic, not functional.
- [x] Calculator **code complete 2026-08-27** — `darkos-calculator.py`. Expression parsing deliberately avoids `eval()`/`exec()` entirely — input is parsed to an AST and walked allowing only numeric literals and +-*/%**, so no other Python construct can ever execute regardless of what's typed or pasted in; unit-tested against both normal expressions and injection attempts (`__import__(...)`, attribute access, etc. all correctly rejected). History panel, click a past result to reuse it. **Runtime-verified under Xvfb/X11** with real keyboard input: `12+8` → 20, then `×3` continuing from that result → 60, both appearing correctly in history.
- [x] Reader, Clipboard manager, Emoji picker, Gallery, Downloads manager **code complete 2026-08-28** — `darkos-reader.py` (Poppler-based PDF rendering, page nav, zoom, `%f`/argv file-open, deliberately PDF-only for v1 — EPUB/CBZ are real follow-ups), `darkos-clipboard.py` (session-only history by design — a persistent plaintext log of everything ever copied is a real privacy footgun on a security-focused OS; explicit pin saves a specific entry to JSON, everything else clears on close), `darkos-emoji.py` (curated ~180-emoji searchable set with recents, not the full Unicode emoji list), `darkos-gallery.py` (thumbnail grid + full-size viewer, GdkPixbuf scale-on-decode), `darkos-downloads.py` (a focused, newest-first Downloads view with quick actions — not a live download-progress tracker, since nothing in DarkOS currently exposes download-in-progress events to hook into; stated as a scope choice, not silently missing). **Phase 4 is now fully code-complete.**
  **Runtime-verified under Xvfb/X11, real files not fixtures:** Reader rendered a real 3-page test PDF (Poppler) with working next-page and zoom. Clipboard picked up three externally-set clipboard values in real time and round-tripped remove/re-copy. Emoji picker's click-to-copy was confirmed via the actual persisted recent-emoji JSON containing the exact emoji clicked. Gallery displayed real generated test images at correct aspect ratios in both grid and full-size view, with next/prev navigation confirmed. Downloads showed real test files sorted newest-first with correct sizes/dates, and Move-to-Trash was confirmed by the file actually disappearing from disk.

## Phase 5: System management
Goal — Settings actually manages the system. This is where most of the original ~90-item list lands, as tabs, not apps
- [x] Settings hub: System, Performance, Config, Devices, Users, Services, Startup, Storage, Fonts, Icons, Themes, Wallpaper, Motion, Designer, Permissions, Accessibility (Speech, Captions, Magnifier, Keyboard, Eye Control) **code complete 2026-08-29** — `darkos-settings.py`, one app per the non-negotiable rule, sidebar + `Gtk.Stack`. Depth is calibrated per tab, not uniform: System/Devices/Users/Storage read genuinely real data (`/proc`, `/sys`, `pwd`, `lsblk -J`, `shutil.disk_usage`) and are runtime-verified against this sandbox's actual values. Fonts/Icons/Themes/Wallpaper/Motion/Designer write through the new `darkos_shell/user_settings.py` store, which `tokens.py` now reads at import — **confirmed by direct test** that a saved accent color/corner-radius/reduce-motion value actually changes `tokens.COLOR_PRIMARY`/`CAIRO_PRIMARY`/`RADIUS_PANEL`/`REDUCE_MOTION`, not just written to a file nothing reads (`REDUCE_MOTION` is wired into the HUD's own rotation speed as the first consumer). Performance/Services correctly attempt the real thing (cpufreq sysfs, `systemctl list-units`) and report the real failure in this sandbox rather than faking data — verified both the real-data path (System, on real /proc values) and the graceful-failure path (Performance, Services, on this sandbox's actual absence of cpufreq/systemd) are each genuinely exercised, not assumed. Permissions is an explicit honest stub (no portal/sandboxing backend exists to enforce anything yet). Accessibility's five sub-tabs save real preference toggles; wiring them to an actual speech engine, live captions, or compositor-level magnification is real follow-up work, stated as such rather than implied.
  **Two real bugs caught and fixed, not shipped:** (1) Startup's toggle used `configparser`, which lowercases all keys by default (`Type`→`type`, `Exec`→`exec`) — would have silently corrupted every `.desktop` file's case-sensitive keys per the Desktop Entry spec on the very first toggle. (2) Even after fixing the case bug, `configparser.write()` reformats `Key=Value` into `Key = Value`, inconsistent with every other `.desktop` file in this repo — replaced with a surgical plain-text line edit that changes only the one value and leaves everything else byte-identical. Confirmed via direct file diff, not assumed.
- [~] Performance profile (Settings > System): the Performance tab reads real per-core CPU governor state where cpufreq is exposed (none in this sandbox — real on actual hardware). Kernel/scheduler *choice* and the Phase 8 first-run-flow integration are not implemented — that's a bigger, install-time-specific piece than a Settings toggle and hasn't been scoped yet.
- [x] Network Center (Wi-Fi, Bluetooth, Connect, Cloud) **code complete 2026-08-29** — `darkos-network.py`. Wi-Fi/Bluetooth shell out to `nmcli`/`bluetoothctl` (the correct approach — NetworkManager/BlueZ own real hardware state, this doesn't reimplement that) and report the real failure rather than a fake device list. **Runtime-verified against two different real failure modes** in this sandbox: `nmcli` exits cleanly with "Could not connect: No such file or directory" (no NetworkManager running) and `bluetoothctl` actually aborts outright (SIGABRT, no D-Bus) — confirmed the app catches both without crashing itself and shows the real error text either way. Cloud tab is a stub (nothing exists to connect to before Phase 9).
- [ ] Connect (Network Center tab): real phone integration on the KDE Connect protocol — notifications, clipboard sync, file transfer, find-my-phone (Zorin Connect-inspired). `pykdeconnect` on PyPI is an early (v0.1.1) reference implementation, not production-ready as-is. **Deliberately not attempted beyond a UI shell** (disabled "Pair New Device" button, honest explanation in place of a device list) — real TLS pairing + mDNS discovery + the packet protocol is a substantial standalone project, not something to half-build alongside sixteen Settings tabs in the same pass.
- [ ] Security Center (Vault, Privacy, Shield, Permissions, Encrypt) — not started.
- [ ] Shield: ClamAV scan engine + fanotify on-access scanning + rkhunter/AIDE integrity checks + quarantine UI (see architecture.md § Security & antivirus) — not started. Unlike Phase 4's apps, this categorically can't be built-and-verified the same way here: fanotify needs `CAP_SYS_ADMIN` and real kernel access this sandbox doesn't grant even in principle, and a real ClamAV/rkhunter/AIDE pass needs the actual daemons and a real filesystem baseline. Writing this blind, with no way to check it actually catches or misses anything, is a worse starting point than not writing it yet.
- [ ] Network transparency dashboard (per-app, plain-language) — reuses PHANTOM's monitoring core. **Blocked on input, not effort:** PHANTOM's source isn't in this repo or this conversation — reusing its actual monitoring core means either Hamza sharing that code, or reimplementing something PHANTOM-*like* from scratch, which risks quietly diverging from what "reuse" was meant to mean here.
- [ ] Backup / Recovery — not started.
- [ ] Dashboard (Performance, Overlay), Mission / Spaces — not started. Mission/Spaces specifically needs real `hyprctl` workspace/client data from a running Hyprland compositor to be more than a mockup — same category of gap as Shield above.
